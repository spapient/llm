# 0007：代价来自一条求和表达式，而不是每个算子手写一遍

- 状态：已采纳
- 日期：2026-11-12

## 背景

`cutile` 的 roofline 只要两个数：`(flops, bytes)`。但这两个数此前由每个算子在自己的语义模块里
手写一遍流量常数：

```rust
// crates/op/src/gemv_i4.rs（改前）
pub fn cost(m: usize, n: usize) -> Cost {
    Cost {
        flops: 2.0 * m as f64 * n as f64,
        bytes: m * n / 2 + m * 4 + n * (m / GROUP) * 4 + n * 4,
    }
}
```

这带来三个具体问题：

1. **新增算子的边际成本不是 0 行机制代码，而是"再写一遍公式"**——一个 int4 GEMV 的流量要同时记得
   权重是半个字节、`scales` 只有 `m/GROUP` 个元素、输出也要写一遍。写错不会报错，只会让 roofline
   的估值偏高或偏低，且没有任何对拍口径能发现它。
2. **公式里的分组因子是隐式的**：`m / GROUP` 到底算"求和维"还是"布局面"，只存在于作者脑子里。
   roofline 的 `flops` 一旦多乘一个因子，`verify` 打印的预测下界就整体偏一个常数倍。
3. **`plan` 想复用也不可能**：`cutile::plan` 只拿到 `Cost`，不认识算子；公式留在算子层，意味着
   每个算子都是一次独立的、无法交叉验证的推导。

## 决策

新增语义层 `crates/einsum`（包名 `llm-einsum`），**拥有** `Expr` / `Extents` / `Operand` / `Access` /
`Bits` / `Axes` / `Cost`。算子只声明两样东西：

```rust
pub const EXPR: &str = "nm,m,ng,n->n";   // 输出缓冲也是左侧的一项
// 操作数：w(i4) / x(f32) / scales(f32) / y(f32, 写)
```

`flops` 与 `bytes` 由这一层推出：

| 量 | 口径 |
|---|---|
| `flops` | 有规约轴时 `2 × Π(参与运算的轴)`；没有规约轴时 `Π(输出轴)` |
| `bytes` | 每个操作数 `ceil(Π(自己的轴) × 位宽 / 8)` 之和（写入同样计费） |

三条明确的"不支持"，都是刻意的：

- **省略号 / 广播**：同一个字母在不同操作数里长度不同，代价模型就必须开始猜形状；
- **同一项内重复字母（对角）**：那是索引变换，不是算子语义，调用方应先 reshape；
- **省略 `->` 的隐式模式**：输出轴顺序会变成一条只有作者记得的排序规则。

**派生轴（`Extents::group`）**是这次决策的关键补丁：`scales[n, g]` 的 `g = m / GROUP` 不是独立的
求和维，遍历 `g` 与遍历 `m` 是同一批元素的两层看法。把它当普通轴会让 `flops` 多乘一个因子；把它
当普通标量又会算错流量。声明成派生轴之后：长度由基准轴推出（不整除即报错），流量按它自己的轴算，
运算次数把它排除在外。

## 为什么不把 `cutile::plan` 搬进 `einsum`

`plan` 是五步流水线 `expand → negotiate → select → substitute → emit` 的第③步，它的输入是 `cap::Path`、
`decl::expand` 与 `prof::Profile`——全是 `cutile` 的中间产物。搬走只有两条路：产生依赖环
（`einsum → cutile` 且 `cutile → einsum`），或者把①②步一起搬走（等于把流水线从中间切开）。
`einsum` 只拿走"语义 → 代价"这一段，`plan` 保留"代价 + 设备峰值 → 时间"这一段，两者以 `Cost`
相接，方向单一。

## 后果

- 新增算子不再写任何流量常数，只写一条表达式与操作数表；
- 表达式与形状不自洽（列数不是分组宽度的整数倍、输出轴没出现在任何输入项里、操作数个数对不上）
  在**构造期**就失败，而不是在 roofline 里静默截断；
- `Model::cost` 因此变成 `fn(usize, usize) -> Result<Cost, Error>`：错误带类别与上下文，`cutile`
  在边界处转成人类可读的诊断；
- `Cost` 的所有权归 `einsum`，`op::model` 只做再导出——`cutile` 的依赖图不变（仍只依赖 `op`）；
- 验收口径：4096×4096 的 `flops`/`bytes` 与迁移前逐位相同，`verify` 的缓存键仍是 `83a3ecdb31cd1225`。

## 未决

- 表达式目前只描述**单个**算子。融合算子（`C = A·B + bias`）要么写成两条式子用 `Cost::plus` 相加，
  要么等 P3 的 plan 表引入"算子组合"再定；两者都不需要改 `Expr` 的文法。
- `Axes` 已经能给出批 / 自由 / 规约 / 分组四类角色，但还没有消费者（`plan` 不做候选比较）。
  等 P3 的 autotune 需要"哪一维可以合批"时直接取用，不新增推导。
