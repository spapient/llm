# ADR 0013：加第二条算子只加数据——稠密 f32 投影

- 状态：已采纳（2026-11-12）
- 影响面：`op`（新增一条注册）、`nn`（格式 → 算子映射多一格）、`cutile`（**零改动**）
- 相关：ADR 0007（代价来自一条求和表达式）、ADR 0011（下界按方向分账）、ADR 0012（量化分组与宽度同源）

## 背景

在本次改动之前，仓库里只有一条算子 `gemv_i4`，而 `nn::WeightFormat::operator` 只把 int4 映射到它。
于是**真实权重一律算不出下界**：safetensors 里绝大多数条目是 `F32`/`F16`/`BF16`，`llm status --weights`
对它们只能报"这个格式还没有投影算子"。这不是缺一条命令，而是缺一条能力：框架声称"配置驱动算子"，
却只有一个算子，而且只覆盖一种编码。

同时，DESIGN §13.2 有一句被反复引用但从未被验证的话：**"新增一格边际成本 0 行"**。只存在一条算子时，
这句话无法证伪——任何"加算子"的动作都可以顺手改机制代码。

## 决定

新增第二条算子 `gemv_f32`（`y[n] = dot(w[n, :], x[:])`），并且**只改数据与语义**：

| 文件 | 内容 | 是否机制 |
|---|---|---|
| `crates/op/ops/gemv_f32.toml` | 骨架 / 轴 / 能力签名 / 布局 / 降级链 | 数据 |
| `crates/op/ops/gemv_f32.k` | 模板：分块点积 + 与 `gemv_i4` 同一批 `@原语` | 数据 |
| `crates/op/src/gemv_f32.rs` | `EXPR = "nm,m,n->n"`、`AXES`、`MODEL`、样本与标量参考 | 语义（第二份实现） |
| `crates/op/src/lib.rs` | `REGISTRY` 多一条 `Registration` | 一条注册 |

`cutile` 的协商、片段拼接、emit、缓存、审计一行未改：它只消费 `OpDecl` 与 `Model`，不认识算子名。
片段层同样一行未改——新算子用的是 CPU 档案里已有的那 9 个 L2 原语（`dot`/`load`/`load_async`/
`commit_wait`/`bar`/`cvt`/`reduce`/`store`，以及量化那条不用、稠密这条同样不用的 `atomic`）。

## 三条刻意的取舍

1. **不把稠密塞进 int4 的语义**。同一份 `[4096, 4096]` 权重，f32 的读下界是 64 MiB，int4 是 10.5 MB；
   用一条算子顶替另一条，就是报一个"错得很像对的数"。格式 → 算子名因此是映射表，不是默认值。
2. **稠密的形状粒度是 1**。`gemv_i4` 要求 `m` 是量化分组的整数倍，那是 nibble 对齐的约束；稠密权重
   没有分组，宽度 100 也应当能算。模板用 `len` 截断最后一块，参考实现按同一块宽累加——两者是同一份
   舍入顺序，所以对拍的 `max_rel_err` 反映的是实现是否一致。
3. **代价仍由一条表达式推出**。`nm,m,n->n` 比 `nm,m,ng,n->n` 少一个派生轴，`flops` 与两个方向的流量
   都由 `einsum` 算，本 crate 不写任何流量常数。

## 被迫一起改的两处（都不是"顺手重构"）

- `op::builtin_named(name)`：此前多处测试用 `op::builtin()[0]` 取"第一条算子"。注册表从一条变两条时，
  按位置取会**静默换人**（`gemv_f32` 排在 `gemv_i4` 之前）。这些调用点改为按名字取；`builtin_named`
  是同一件事的公开入口，与 `model(name)` 对称。
- `nn::Bounds::of_op` 与一条测试里的 `(model.cost)(m, n)`：语义表已改为收 `ShapeContext`（ADR 0007 的
  具名轴），这两处是并行重构留下的中间态，随本次一并修好。

## 后果

- `llm status --weights` 对 f32 权重第一次给出真实下界（读 = 权重 + 输入向量，写 = 输出向量）。
- `cutile verify --op gemv_f32 --devices cpu` → `✓ L2 | variant pipe2 | max_rel_err 0.000e0`：新算子
  在真机上编译执行并与标量参考逐元素一致，用的是与 `gemv_i4` 相同的 9 条见证。
- **f16 / bf16 仍然算不出下界**，而且现在理由更具体："还没有 16 位元素的投影算子"。补齐它们需要一条
  `cvt` 的 16 位片段（CPU 档案现在只声明 `f32/i32/i8`）与一个 16 位模板，那是片段层与档案层的改动，
  不属于"加一条算子只加数据"的范畴——把它记在这里，而不是让它看起来像已经支持。

## 如何复现

```bash
cargo test -p llm-op -p llm-nn            # 声明可装载、代价与下界逐项对上
cargo run --bin cutile -- verify --op gemv_f32 --devices cpu   # 真机对拍（L2）
cargo run --bin llm -- status --weights <f32.safetensors>       # 真实文件 → 层栈 → 非零下界
```
