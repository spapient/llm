# 0017：kernel AST 引入与运行时张量 IR 冻结

- 状态：已采纳
- 日期：2026-11-12

## 背景

`cutile` 当前的代码生成是纯文本路线：`.k` 模板经 `substitute` 文本拼接后直接产出 C 源码，
字符串是唯一中间物。终局要求多后端（CUDA/Metal/ROCm/MUSA），纯文本路线意味着同一原语要
在每个后端各维护一份文本，语义一致性靠人工，且后端越多迁移成本越高。实测片段层已出现
`cpu/intel/metal` 三个 vendor、30 个片段文件，其中 `dot` 三后端正文逐字相同，重复已经产生。

另一条路是直接引入 CubeCL 式的运行时张量 IR（跨算子、JIT、融合），但当前没有消费者、
没有真机数据，其主体（cubecl-core 16K SLoC）是独立的大投入，现阶段引入是纯成本。

## 决策

分两级处理，现在只做第一级：

1. **引入单 kernel 级结构化 AST（L1）**：在 substitute 与 emit 之间新增 AST 层，表达 kernel
   内的声明、控制流、原语调用、槽位绑定；后端收敛为 AST printer，正文同构片段上移，后端
   只保留真正分叉的 lowering。缓存指纹改为 AST 规范编码的 FNV。
2. **运行时张量 IR（L2）显式冻结**：跨算子融合、运行时 JIT、动态形状重写不在本批实现。

AST 不违背「无隐藏优化阶段」哲学：它是可见、可打印、可哈希的数据结构，放弃的只是
「字符串是唯一中间物」这一手段。

## L2 解冻条件（同时满足，且须先过新 ADR）

1. 单 kernel 真机对拍全部达到 L2 证据级，且性能达到 roofline 的 70%（L3）；
2. roofline 证据证明 decode 场景存在跨算子融合收益（带宽天花板被融合突破，而非估算）。

## 后果

- 新增后端只加 printer 与工具链路径，AST 与算子注册表零改动；
- P1 阶段必须通过双射对拍：同一 `.k` 经 AST 渲染的 C 文本与重构前逐字节一致；
- 禁止在未经 ADR 的情况下新增跨 kernel 重写模块，门禁脚本将其作为检查项；
- 不新增 crate，AST 作为 `cutile` 内模块存在，不放大微 crate 问题。
