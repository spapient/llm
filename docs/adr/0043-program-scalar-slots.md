# 0043：程序标量通道——定长类型化闭集标量槽（D9）

- 状态：草案（M1-B6 落地槽位结构与 Node/Launch 承载；rope 算子接线与标量注入闭包随对应刀落地；§5 定形变长批逐序列位置表通道归属）
- 日期：2026-11-17（2026-11-18 补 §5：变长批逐序列位置表通道）
- 相关：[0027](0027-kernel-registry-and-fragment-contract.md)（注册表与算子挂载）

## 背景

`engine::exec::Launch` 此前只有 `grid` / `block` 三轴几何；像 `rope_f32` 这类算子还需要
**解码位置**这类语义标量。落地前有三条容易走偏的通道：

1. 把位置编进一个 1 元素 f32 缓冲，走 `Program::run` 的 `inputs` 切片通道——标量被当成张量
   参与 dtype / 形状校验，缓冲通道混入语义参数；
2. 在执行上下文里放字符串键 → 值的 `HashMap`，按算子名查表取标量——热路径出现 map 查找，
   槽位集合没有闭集约束；
3. 把头数 / 头宽这类静态几何也塞进标量槽——几何事实已有 `op::MODEL.shape` 唯一来源，复制
   一份会漂移。

## 决策

### 1. 定长类型化闭集结构挂在 Launch / Node

新增 [`ScalarSlots`](../../crates/engine/src/exec.rs)：定长、类型化的标量槽结构，随 `Launch`
拷贝、由 `Node` 透传。首批槽位**仅** `rope_position: Option<u32>`（`rope_f32` 的 `pos`）。
槽位集合冻结在本 ADR：新增槽位必须修订本 ADR 并在结构上加类型化字段，不开放任意键值对。

### 2. 缓冲切片通道签名不变

[`Program::run`](../../crates/engine/src/exec.rs) 的 `inputs` / `outputs` 切片签名保持原样；
位置这类语义参数不编进 1 元素缓冲。标量槽不是第二份缓冲账，也不是标量上下文 `HashMap`：
无字符串键查表，热路径固定结构直取字段。

### 3. 静态几何仍取算子声明

`heads` / `head_dim` 等静态几何继续以 `op::MODEL.shape` 为唯一事实源；标量槽只承载运行期
逐位置变化的语义标量，不复制几何宽度。

### 4. 未接算子仍按名拒绝

`rope_f32` 尚未接入模型路径：槽位结构就位，但该算子在 serve 内核子集里仍按名拒绝（既有
`an_unregistered_kernel_is_refused_by_name` 口径不变）。标量到内核闭包的注入随 rope 接线刀
一起落地；本刀不预埋第二份算子映射。

### 5. 变长批：逐序列位置表走输入缓冲，不扩标量槽

M2-2 变长批中各序列准入时间不同，第 `b` 段要独立的旋转位置 `positions[b]`；op 批量入口
`rope_f32::forward_batch(positions: &[usize], x, out, head_dim)` 已就位。这条运行期表的通道
归属按下述口径定形：

- **位置是逐序列时间戳，不能从缓冲宽度反推。** 注意力历史长度 `hist = k.len()/(heads·d)`
  这类几何事实由缓冲长度派生；位置不是几何，批内各段取值不同，必须由装配侧显式提供一张
  长度 = `batch` 的表。
- **不进 `ScalarSlots`。** 槽是定长、`Copy` 的类型化闭集，热路径固定字段直取；塞一张变长
  数组会破坏 `Copy` 与定长闭集口径，槽集合仍冻结在本 ADR，不为批形态开数组字段。
- **走既有输入缓冲切片通道**（`Program::run` 的 `inputs`）：与既有整数经 f32 缓冲承载的先例
  同口径——查表层把 token id 折成 `f32` 收进输入缓冲。位置元素以 `f32` 承载、内核侧
  `as usize` 取回；解码位置远小于 `2^24`，f32 整数无损，越界精度由装配与算子校验守。不为这
  张表新增整数 `Buffer` / `View` 变体（`Buffer` 仅 `F32` / `U8` 两路 lane）。
- **布局**：整块 `f32`，长度 = `batch`，`positions[b]` 对齐准入序第 `b` 段；`View` 是整块
  切片、无 offset / stride，段对齐由装配绑定完成，与现有批缓冲同口径。位置表是一条**独立输入
  操作数**，不与特征缓冲混编；这与 §2 否决的"单标量编进 1 元素缓冲"性质不同——那条否决的是
  把单个语义标量伪装成张量参与形状校验，批表是与批同宽的独立运行期表。
- **单序列通道保留。** `ScalarSlots.rope_position` 仍是未批化 / 单序列 rope 的位置通道；批 rope
  节点绑位置表输入操作数后不再读标量槽，同一节点上两条通道不并存。

装配期给批 rope 节点多绑一条位置表输入编号、内核从 `inputs` 取位置表、每步覆写该缓冲，随块链
整批接线刀落地；本 ADR 只定通道归属与形状，不预埋空节点、空编号或第二份算子映射。

## 备选方案

- **位置走 1 元素 f32 缓冲**：拒绝。标量被拉进张量形状/dtype 校验，缓冲通道混入非张量参数，
  后续每颗内核都要分辨"这是缓冲还是标量"。
- **字符串键 `HashMap` 标量上下文**：拒绝。热路径 map 查找；槽位无闭集，拼写错误到运行期才
  暴露，与既有闭集常量表口径不一致。
- **几何复制进标量槽**：拒绝。头数/头宽已有 `op::MODEL.shape` 事实源，双写必然漂移。
- **标量槽扩 `Vec<u32>` / 位置表字段承载批位置**：拒绝。变长数组破坏槽的 `Copy` 与定长闭集，
  热路径引入堆分配；逐序列运行期表归输入缓冲通道（§5），不回流标量槽。
- **为位置表新增整数 `Buffer` / `View` 变体**：拒绝。为单个语义表扩 engine 通道面；仓内已有
  整数经 f32 缓冲承载的先例，复用既有 lane 即可，不新立整数 lane。

## 后果

- 新增标量槽位 = 改 `ScalarSlots` 结构 + 修订本 ADR；不引入运行期键表。
- 逐序列运行期表（批位置表等）归输入缓冲切片通道；标量槽仍只承载单值语义标量。
- engine 不解释槽位语义：字段只承载数值，语义归属算子声明与装配侧。
- 已落地回归：默认槽位全空；rope 位置经 Launch → Node 往返一致（`engine` exec 测试）。
