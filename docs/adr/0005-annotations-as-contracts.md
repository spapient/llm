# 0005：注解生成契约，不生成注册表

- 状态：已采纳
- 日期：2026-11-12

## 背景

`nn` 的层声明原本散落在三处：构造函数里的名字与算子、`impl Layer` 的三个方法、测试里的断言。
改名或删算子时，三处必须同时改，而编译器只保证其中两处一致。

同时仓库有一条供应链约束：**workspace 零外部依赖**（`Cargo.lock` 里只有本仓库成员）。
引入 `syn` / `quote` / `proc-macro2` 会打破它，且三条依赖需要 `deny.toml`、审计 job 与
版本治理才能保持一致——而注解文法本身只有三种键。

## 决策

新增 `crates/annotation`（proc-macro，工具成员），提供 `#[layer]`：

```rust
#[nn::layer(name = "lm_head", out = [4096], ops = ["gemv_i4"])]
pub struct LmHead;
```

展开成三块，全部可见、可预测：

1. 原样保留的被标注项；
2. `impl Type { fn __layer_spec() -> &'static LayerSpec }` 与 `impl nn::Layer for Type`，
   规格用 `OnceLock` 构造一次；名字带 `__layer_` 前缀，不占用用户可能想用的方法名；
3. 一个 `#[cfg(test)]` 模块，调用一次 `__layer_spec()`——**算子被删而注解没改时，`cargo test` 失败**，
   而不是等到 emit 阶段才报未知算子。

实现按"能不能测"切成三层：`syntax`（token 模型 + 文法，完全不碰 `proc_macro`）、`codegen`
（声明 → 代码，纯字符串拼接）、`lib`（`TokenStream` 适配与 span 定位）。理由是
`proc_macro::TokenStream` 只在展开期可用——把文法写死在它上面，等于让每条错误路径都无法测试。
适配层同样做了依赖倒置：`Streams` trait 把"读 token、拼 token"抽出来，测试用字符串实现它，
于是"出错时保留被标注项"这类容易退化的行为也有断言。

解析器手写（约一百五十行），错误一律走 `compile_error!`，并且**指在写错的那个 token 上**
（span 取自属性或被标注项里的真实 token，而不是整个调用点），只报**注解自己的文法**：
未知键、重复键、缺必填键、非字面量、带转义序列的字符串、零宽轴、空算子集、泛型参数、
非 `struct`/`enum`。

## 为什么不建注册表

`inventory` / `linkme` 式的运行期注册表很诱人，但它会把"有哪些层"变成**第二事实源**：
注册表里有一条、代码里没有（或反过来）时，只有运行到那一行才会发现。注解 + 编译期实现
没有这个问题：类型不存在就编译不过，算子不存在就测试不过。

## 不用 `syn` 的代价与边界

- 代价：文法固定为 `name = ".."`、`out = [..]`、`ops = [".."]`，不支持表达式、常量、嵌套属性；
- 边界：需要更复杂文法时**先扩文法再扩解析器**，而不是顺手引入 `syn`——一旦引入，
  "零外部依赖"就变成"少量外部依赖"，后者需要一整套治理才能维持。

## 后果

- 新增一个固定形状层只需一行注解，且形状里的类型错误是编译错误（`out` 只接受十进制整数）；
- `nn` 与下游 crate 用同一套展开：`nn` 里靠 `extern crate self as nn;` 让 `::nn::..` 指向自己；
- 注解**不能**表达运行期才知道的宽度（如 `Linear::new` 的参数），那类层继续用构造函数，
  两者共用 `LayerSpec::new` 的校验路径；
- 宏生成的测试会让"声明与数据脱节"变成红灯，但它不替代 `cutile verify` 的真机证据。

## 补充（2026-11-13）：`dtype` 名 → 变体名收敛到 `dtype`

本 ADR 采纳时注解**零依赖**：`dtype` 名 → 变体名在 `codegen` 手写一份映射，靠
`tests/contracts.rs` 与词汇表 `Debug` 名双向核对。后续 `crates/dtype` 提供
`DType::variant` 作为变体名唯一事实源（缩写词全大写规则也住在那里），注解改为依赖
`dtype` 直接取变体名，删掉了那份手写映射与门禁里的镜像映射。

这不违反本 ADR 的供应链动机：`dtype` 是 workspace 内部 L1 零依赖成员，`syn` / `quote` /
`proc-macro2` 仍未进入 `Cargo.lock`。被拒绝的仍是"给过程宏拉一条到 `prof` 的依赖边"——
`prof` 会带入 `diagnostic` 的传递依赖，而注解只需要类型身份，`dtype` 已足够。
