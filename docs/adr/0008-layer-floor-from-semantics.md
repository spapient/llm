# 0008：层的性能下界由算子语义推出，不手写常数

- 状态：已采纳
- 日期：2026-11-12

## 背景

`cutile` 的 roofline 在 **kernel** 层给出两件事：这条片段至少要搬多少字节、算多少次浮点。`bench`
再用真机跑出事实，`audit::Verdict` 把两者比较，得出"达成率"。这条链在 kernel 层是闭合的。

但**层**这一侧是空的。`nn::LayerSpec` 只声明了"名字 + 输出形状 + 算子名"，于是出现了三个具体问题：

1. **"这一层至少要多快"没有出处。** 想知道一个 4096×4096 的 int4 投影每 token 到底要搬多少
   字节，只能现场拿计算器估一遍，估完还没有地方可存。跨会话、跨人重复估算，结论无法复现。
2. **优化收益无法归因。** 把两个算子融合、把权重换成 int4、把布局改成正规形，各自的收益是多少？
   kernel 的 `bench` 只能给出"融合后这一条片段快了 X%"，而"这一层本来就不该超过 Y"这个上界
   从来没有被写下来，所以"快了多少"永远是相对上一次测量，而不是相对物理下界。
3. **手写常数会腐烂。** 如果让每个层自己写 `bytes` / `flops`，那就等于在 `op` 之外多出第二份流量
   公式；算子改一次位宽或分组，两处就开始各说一套，而且没有任何口径能发现。

## 决策

新增 `nn::Bounds`，并且**只允许从算子语义推出**：

```rust
pub struct Bounds { bytes: u64, flops: f64 }

impl Bounds {
    pub fn of_op(op: &str, m: usize, n: usize) -> Result<Self>; // 唯一构造入口
    pub fn plus(self, other: Self) -> Self;                    // 一串层的总下界
    pub fn intensity(&self) -> f64;                            // flop/字节（roofline 横轴）
    pub fn calls_per_second_ceiling(&self, peak: f64) -> f64;  // 调用方给峰值
}
```

四条约束把"第二个事实源"挡在门外：

1. **`of_op` 是唯一入口**，它调用 `op::model(op).cost(m, n)`——与 `cutile::plan` 读的是同一份
   `einsum` 语义。`nn` 里没有任何流量常数。
2. **字段私有、没有 `new`**：调用方不能拼一个"我以为是这么多"的下界出来。
3. **`Bounds` 不认识设备**：峰值带宽由调用方传入（`prof` 拥有它），因此这个类型仍然可以离线
   复现，不违反 L2 数据层的"不认识厂商/峰值"。
4. **`LayerSpec::new` 同时要求算子有语义表**：只声明不实现的算子推不出下界，也就无法对拍，
   因此在层构造期就被拒绝（`Code::Missing`），而不是等到 emit 或 verify。

`Linear::bounds()` 因此是一行：`Bounds::of_op(Linear::OP, in_features, out_features)`；
`Linear::OP` 是唯一一处写算子名的地方（构造与下界共用）。

## 后果

- 组装点 `llm status` 多一行：`blk.0.attn_q 4096 → ≥ 10.52 MB / 33.6 MFLOP，强度 3.19 flop/byte`。
  这一行是**声明**，`cutile bench` 的达成率是**事实**，两者相减才是"融合/量化/布局赚了多少"。
- 三个原本只能在人脑里成立的事实变成了断言：int4 权重让强度落在 3.19 而不是 f32 的 1.0；
  4096 方阵的第一项流量就是 8 MiB（权重）；量化 GEMV 的规约轴不是 32 的整数倍时**根本没有**
  合法内核，所以"下界"应当失败而不是给个数。
- 层能构造、但形状对算子不合法，这是一个**真实的中间态**（`Linear::new("odd", 8, 4)` 合法，
  `bounds()` 失败）。它现在被写成测试，而不是留给人去踩。
- 代价是 `LayerSpec` 的校验多一条：声明了算子但没写 `op::model` 的算子从此进不了层。这是有意
  的——层的产出物必须可对拍、可有下界，否则它只是一个字符串列表。

## 未决

- 下界目前按"一次调用"给，还没有乘上批大小与层数；整模型下界需要 `weights` 能列出真实层清单
  之后再聚合（`Bounds::plus` 已经是那一步需要的全部算子）。
- `bytes` 仍是读写合计：`prof` 没有区分读/写峰值，拆开就暂时没有消费方。等档案里出现读写不对称
  的峰值（某些设备确实如此）再拆，而不是先加两个没有读者的字段。
