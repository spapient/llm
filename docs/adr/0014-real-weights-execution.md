# 0014 真实权重执行：同一件内核，换一份样本

- 状态：已接受
- 日期：2026-11-12
- 相关：[0008](0008-layer-floor-from-semantics.md)（层下界来自算子语义）、
  [0009](0009-real-weights-to-model-floor.md)（真实权重 → 层栈 → 模型下界）、
  [0013](0013-dense-projection-operator.md)（加第二条算子只加数据）

## 背景：证据有了，但从来没有算过一份真实权重

到 ADR 0013 为止，仓库能回答两个问题：

1. `cutile verify --devices cpu` —— "这台机器能不能算这条算子"（L2，与标量参考对拍）；
2. `llm status --weights f` —— "这些层至少需要多少流量"（纯算术，不需要设备）。

两者之间有一个洞：`verify` 用的是**算子自己的确定性样本**（`Model::sample`），所以它证明的是
"内核能算它自己造的数"。真实权重从来没有进过内核——框架至今没有真正算出过一个数。

这个洞不是靠"多跑几个形状"能补上的：真实数据与合成样本的差别不在大小，而在**血缘**——它来自
文件里某条条目，而不是算子代码里的一个公式。

## 决策

四条，每条都在它唯一该在的层落地：

### 1. `op::model::bind`：真实数据进入样本的唯一入口

```rust
pub fn bind(model: &Model, m: usize, n: usize, x: &[f32], w: &[f32]) -> Result<Sample>
```

- **只替换 `x` / `w`**：标量（`M` / `N` / `gsz`）、输出缓冲、其余输入仍来自 `Model::sample`。
  真实数据不该顺手改掉 ABI——那会让"签名与样本对齐"这条校验失去意义。
- **先校验形状粒度**（`m` 是 `Model::group` 的整数倍），再校验长度，最后才换入：把"数据不对"
  与"内核算错"分开。
- **只接受 f32 权重缓冲**：量化算子的 `w` 是打包字节，塞 f32 进去字节数对而含义不对，因此以
  `Code::Unsupported` 拒绝，而不是让内核去解读半份字节。这条拒绝理由点名"先按算子声明的分组量化"。

`Sample::set` 是按**名字**换缓冲的最小实现：名字是算子契约的一部分（模板形参名、`reference` 读的
缓冲名、`@prim(...)` 实参名是同一个字符串），顺序属于签名，不属于样本。

### 2. `audit::execute` + `audit::Execution`：同一件流水线的第二个入口

```rust
pub fn execute(catalogue, settings, op_name, device, sample) -> Result<Execution>
```

与 `verify` 共用协商 → tile → 拼接 → emit → 编译 → 执行的同一段代码，差别只有三点：

- 样本由调用方给，因此只跑一份，不做形状矩阵；
- **执行前要求见证证据**（`Evidence::basis == Basis::Executed`）：没有执行证据的后端跑出来的数
  不是结果，只是现象；
- 对拍不通过是错误（`Code::Invalid`），不是"环境问题"——它说明产物与它自己声明的语义不符。

返回的 `Execution` 同时给内核输出与标量参考：让调用方自己决定要不要展示差值，而不是把两者混成
一个布尔。

### 3. `nn::Layer::linear`：只有按形状构造的层能被真实数据执行

`#[layer]` 注解出来的层只有名字、输出形状与算子列表，**没有参数表**；给它喂权重等于让每个层
自己再发明一遍参数绑定。因此 `linear()` 默认 `None`，`Linear` 覆盖为 `Some(self)`。

这条约束把"哪些层能执行"写成类型问题，而不是运行时约定。

### 4. `llm run --weights`：在组装点串起来

```bash
cargo run -p llm -- run --weights model.safetensors             # 默认确定性输入图案
cargo run -p llm -- run --weights model.safetensors --input 0.1,0.2,0.3,0.4
```

- **只跑一条连续链**：某层的输入宽度与当前向量不等就停下并说明（不猜"是不是该换一份输入"）；
- **遇到没有算子的编码就停下**（f16 / bf16 / i8 / 分组不明的 4 位打包），理由来自
  `WeightFormat::unpriced_reason`；
- **每层只读自己那条条目**（`File` + `Loader`，按需读），不把整份文件搬进内存；
- 停下来不是错误：前 N 层的结果是真的，后面的层只是这一版不支持——这一点写在输出里。

## 证据

- 两层稠密链（`blk.0.attn_q 8→4`、`blk.0.attn_o 4→4`）跑通，输出
  `-0.195312、-0.765625、-1.468750、-2.968750`，与独立手算（Python，同一份行主序 `[out, in]`）
  逐位相同；每层 `max_rel_err = 0`、片段 51 行、变体 `pipe2`。
- `op`：`bind` 的 4 条测试（注入位置、拒绝打包字节、长度不符、形状粒度）。
- `llm`：2 条端到端测试（两层链跑通；第一条算子对**真实字节**的算术与手算逐位相等）。

## 后果与边界（如实记录，不伪装成已支持）

- **16 位权重仍不能执行**：`F16` / `BF16` 没有算子（ADR 0013 未做项），`U4` 是打包字节
  （`bind` 明确拒绝）。因此本命令今天覆盖的是 f32 稠密模型。
- **样本仍以 C 字面量内嵌进 harness**：大层（例如 4096² f32 ≈ 190 MB 源文本）会让编译变得不切实
  际。真实大模型需要一条二进制数据通道（数据落盘 + `argv` 传给 harness + 数据摘要进产物身份），
  这是下一步，不是本版已解决的问题。
- **只算一层一次调用**：批大小为 1，没有注意力、KV 与采样；"跑一个 token"仍需 `kv` / `engine`
  接入。
- 输入向量默认取确定性图案（`(i % 8) * 0.125 - 0.5`）：不给输入也必须可复现，与 `verify` 同一条
  要求。
