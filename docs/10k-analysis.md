## 三、为什么业界框架那么大——根因分类

1. **Burn（369k）= 广度产品**。39 个 crate 覆盖 nn/train/optim/vision/rl/dataset/remote/router/flex/store/instrument，
   后端用泛型 trait 塔抽象；最大单文件群是 burn-backend-tests（69k 行后端对拍矩阵）与 burn-flex（40k）。
   它的规模是“功能清单”堆出来的，不是机制复杂。
2. **candle（193k Rust）= 模型动物园 + 后端重复**。一模型一文件约占 43%，cpu/cuda/metal 各有一套后端目录，
   再加 37k 行非 Rust kernel。
3. **cubecl（291k）= 编译器税**。IR、fusion、dispatch 是一整套编译器，这是“造平台”的固定成本。
4. **llama.cpp（1.07M）= 矩阵税**。芯片架构 × 后端语言的 kernel 笛卡尔积，每加一台设备加一列。
5. **vllm.rs（78k）= 单体服务**。没有 DSL 分层，调度、执行、协议长在一起。

共同模式：**它们都在“复制实现”，而不是“组合数据”**。

## 四、本仓库已经做对的方向（差异化资产）

这些是真实存在、且业界主流没有同时做到的东西：

1. **数据驱动 kernel，无 IR**：算子 = 声明（.toml）+ 模板（.k）+ 片段（数据），emit 后交给原生编译器，
   框架不造编译器、不做 lowering。
2. **代价语义单源**：一条 einsum 求和表达式推出 flops/流量，roofline 只消费数对，不认识算子名。
3. **证据分级（L0–L3）**：协商同时要求“档案写了 L2”与“这次见证真跑通”，未验证能力视为不具备。
4. **单一错误类型 + 退出码映射**；**一个类型一个主人**；配置的机制与身份分离。
5. **零外部依赖、unsafe 全仓 deny**。

这正是 Unix 组合式架构：**机制与策略分离、数据即接口、闭集代替枚举散落**。方向领先，问题在实现密度。

## 六、万行目标：可行性裁决与预算

**结论：可行，但前提是做减法，不是重写。** 运行时 7.6k 已达标，要把平台从 15k 压到 2–3k。

### 6.1 目标预算（生产 Rust，硬上限 10,000）

| 模块（合并后） | 职责 | 预算 |
|---|---|---:|
| base | 错误类型、配置、路径、退出码 | 800 |
| semantic | einsum 代价 + 算子声明 + 模板/片段装载 | 1,800 |
| kernel | 协商/拼接/emit/编译/内容寻址缓存 | 1,800 |
| runtime | 分配/张量/布局/提交契约 | 1,200 |
| model | 权重读取/量化推断/层栈/KV | 1,400 |
| train | 反向图/调度/重放/训练缓冲/检查点 | 1,800 |
| serve | 连续批/端点/帧协议/分词边界 | 1,200 |
| entry | 两个 bin 的组装与排版 | 300 |
| **合计** | | **10,300 → 收紧到 9,500** |

### 6.2 达成手段（按收益排序）

1. **31 crate → 8 模块**：同层小 crate 降为模块文件，crate 边界只留给真正独立的编译单元；
   架构门从 709 行缩到只校验模块集合与方向。
2. **解析器收敛到一处**：手写 TOML/JSON 只保留一份实现全仓共用；或接受唯一外部依赖（toml+serde），
   用约 1,000 行依赖换掉 5,000 行手写解析——这是需要显式拍板的取舍。
3. **删除 annotation 宏**：`#[layer]` 的 1,105 行用普通构造函数替代（组合式风格本就偏爱函数而非宏）。
4. **审计收敛为一个报告器**：audit + tool + witness 三处排版合一；fuzz/benches 移出 members。
5. **缓存只留内容寻址**：砍掉 GC ledger、cache why、状态台账，保留 key/artifact/复用计数。
6. **删除孤儿与未接面**：benches 移出；exec 的 Executor 要么在本阶段给 CPU 实现，要么随 engine 一起合并。
7. **入口修正**：根目录改虚拟 workspace，两个 bin 移到 `crates/entry`；删掉 L7 里违反“不定义新类型”的
   `LmHead`（下沉到 model 模块），cutile bin 的 859 行排版逻辑下沉到报告器。

## 七、质量与性能：如何同时成立（含诚实边界）

### 7.1 “质量强 N 倍”的可验证口径

- 密度：核心机制集 10k vs burn 369k，**机制代码约 1/37**；零重复实现由架构门强制。
- 纪律保留：单一主人、单一错误、零外部依赖、unsafe deny、clippy -D warnings、doc 零警告。
- 测试转型：13k 行单测 → golden 对拍 + 标量参考 + 少量属性测试，每条机制至少一个可执行证据，
  测试/生产比受控但证据不降级。
- 诚实边界：这是**结构质量**领先，不是功能广度领先；没有模型动物园、没有 vision/rl。

### 7.2 性能主张的可证伪口径

- 性能来源只有三处：数据驱动特化（每形状一份产物）、原生编译器做寄存器/调度、
  引擎层分页 KV + 连续批 + 量化；框架层零动态分发、零 IR 往返、零拷贝视图。
- 对外只报可验证的门：roofline 达成率、`max_rel_err = 0` 对拍、产物复用率。
- **诚实边界**：不宣称手搓 kernel 全硬件超过 cuBLAS/llama.cpp；目标是“在 roofline 包络内由原生编译器
  达成高达成率”，超出包络的特化（wmma/wgmma 等）按阶段以片段数据接入，不写进框架本体。

## 八、风险与决策点

| 决策点 | 选项 | 代价 |
|---|---|---|
| 依赖策略 | 继续零依赖手写解析 / 引入 toml+serde 单依赖 | 前者多 ~4k 行，后者破零依赖原则 |
| 加速器路径 | 本阶段只保 Metal 或 CUDA 一条 | 另一条停在 L1 档案 |
| crate 合并 | 31 → 8 模块 | 失去编译期并行与强制边界，靠架构门补偿 |
| 行数治理 | 新功能先给行数预算（预算棘轮） | 超预算即红灯，功能排队 |

## 九、IR 模块现状（2026-11-12 补记）

新增 `crates/ir` 目前是 `cargo new` 原始模板（14 行 `add(2,2)`），不是 IR：

- 架构门 **失败 2 项**（ir 无依赖边、层表与成员不一致）；clippy **5 个 warning**，CI `-D warnings` 会挂。
- 违反 ADR 0004（禁止 `add(2,2)` 占位）、新增成员三步、依赖边规则；包名缺 `llm-` 前缀。
- “无 IR”是核心论点（DESIGN §1/§10）：放弃跨算子融合是显式接受的取舍；cutile 已有 Plan/Path/Proof
  等可打印中间产物承担可解释性。cubecl 291k 是通用 IR 的实测成本。

待拍板的三个方向：

| 方向 | 内容 | 后果 |
|---|---|---|
| 移除 ir（推荐） | 删除模板，恢复无 IR 论点 | 门禁 6/6、CI 绿；P3 触发条件满足再以 ADR 重建 |
| 保留位置 | 归拢现有中间产物到 ir，不写 pass | 需补文档、依赖边、层表、ADR |
| 通用 IR | 融合 + autotune + pass | 新 ADR 推翻 DESIGN §1/§10，万行预算作废 |

重建 IR 的触发条件：实测算子边界开销可量化且 roofline 未达带宽上限，或片段无法表达所需融合。
